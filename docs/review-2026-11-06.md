# MC Toolbox 启动器调研与功能审查

审查基线为 `main@498f80f`（v1.14.1）。竞品资料查阅于 2026-11-06。上一轮建议中的安装空间预估、下载线路诊断和整合包续传已经交付，这次对照的是玩家还需要切出启动器才能完成的操作。

## 建议优先尝试的功能

| 顺序 | 同类启动器已经提供什么 | MC Toolbox 可以怎样复用已有能力 | 首版验收 |
| --- | --- | --- | --- |
| 1 | 官方启动器可为常玩的世界创建 Quick Play 入口，Modrinth App 的首页可直接回到近期世界。[Minecraft Launcher](https://www.minecraft.net/en-us/download) · [Modrinth App 更新记录，0.9.4](https://modrinth.com/news/changelog?filter=app) | 在实例的「世界」卡片增加「进入世界」，再把最近一次成功进入的世界放到首页。现有世界列表已读出存档目录名和游玩时间，启动计划已能按版本清单生成多人直连参数。首版只给声明支持单人 Quick Play 的版本传世界参数。 | 两个实例各有一个同名世界，入口能打开对应实例的存档。存档移动或版本不支持时，入口给出原因并允许普通启动。 |
| 2 | Modrinth App 可从日志页分享普通日志。其帮助中心特别指出 JVM 崩溃日志可能含访问令牌。[Modrinth 日志指南](https://support.modrinth.com/en/articles/9005261-minecraft-logs) | 在已有「复制」「下载」旁增加「导出求助报告」。复用崩溃诊断和启动命令预览的脱敏规则，合并游戏、加载器、Java 版本及相关日志片段，导出前可预览。首版只生成本地文件，原始 JVM 转储单独处理。 | 用含访问令牌、私有服务器地址和 Windows 用户目录的测试日志导出。玩家能看到出错模组和错误堆栈，敏感字段在预览和文件中均被遮盖。 |

| 4 | HMCL 可订阅服主托管的静态整合包清单；Technic Launcher 通过 Solder 按组件复用已缓存的版本。[HMCL 服主教程](https://docs.hmcl.net/modpack/serverpack.html) · [Technic Solder 项目](https://github.com/TechnicPack/TechnicSolder) | 为现有群入服配置增加可选的服主更新源。先对一个 HTTPS 清单做手动检查，复用整合包差异预览、文件哈希校验和下载中心。区分服主发布的文件、玩家修改的配置和受限分发的文件。 | 清单中只改一个 JAR 和一个配置项时，仅请求缺少的内容。配置有本地改动时先展示差异；校验失败后旧实例仍可进服。 |
| 5 | Prism Launcher 支持从命令行按实例启动。[Prism CLI 文档](https://prismlauncher.org/wiki/getting-started/command-line-interface/) | 在实例菜单生成 Windows 桌面快捷方式，只存稳定实例 ID。交给现有启动、进程接管与错误面板处理，方便服主给测试实例分别建入口。 | 启动器开着和关闭时分别双击同一快捷方式，都启动指定实例；实例改名后仍然可用，已删除或正在运行时有明确反馈。 |

若只排一项，建议从「进入世界」开始。已有的世界列表提供了入口和数据，验收也能用两份离线存档完成。服主订阅涉及更新来源、分发权限和本地配置冲突，适合在单独一轮实现。

## 修复记录

| 用户操作 | 原来的问题 | 修复与验证办法 |
| --- | --- | --- |
| 在实例设置中填写 JVM 或游戏参数 | 带双引号的 Windows 路径会丢反斜杠。旧版本清单中单独指定本地库目录时，启动器还会漏掉装载游戏主类所需的 classpath。 | 启动计划保留普通路径和 UNC 路径，按双引号前反斜杠的奇偶处理转义。独立判断 classpath，并从项目发布元数据读取传给游戏的启动器版本。回归覆盖 Java agent 路径、转义引号及旧版清单。 |
| 在设置中迁移存储目录 | 好友配置和皮肤衣柜可能随运行数据迁移。好友页已经打开时，还会继续使用旧的接收目录和缓存路径。 | 单项或整组迁移按配置归属搬运，切换好友存储并更新接收记录和下载偏好中的受管路径。隔离场景核对迁移后打开旧接收文件、读取缓存图片、保留另存到外部的文件，以及重启后读取配置。单项目标拒绝相对路径。 |
| 清除好友接收记录 | 如果手动把下载位置选为接收根目录，旧的清理逻辑会递归删除文件所在的整个目录，连带删除其他文件。 | 按传输 ID 和相对路径识别该条记录的暂存文件，逐文件删除，仅回收空的传输子目录。覆盖默认位置、另存目录、手选接收根目录。 |
| 在默认端口已占用时打开翻译工作台 | 当 8636 上的另一个服务也响应 `/api/status`，启动器会打开它；真实翻译引擎实际已监听 8637。 | 源码版从本次子进程的启动输出取得实际端口。对可能缓冲输出的独立翻译引擎 EXE，启动时显式指定空闲回环端口。两种方式均核对服务标识和状态响应。 |
| 打开并刷新长群聊 | 阅读消息和计算未读数时，每次轮询都遍历整个群的消息。写盘失败后，未保存的消息也会占用重试 ID。 | 按群缓存时间、发信人和消息 ID 的索引。乱序历史保留日志中的原始顺序，同毫秒消息沿用原游标语义。发送按群排队，成功追加到 JSONL 后才进入缓存。用写入失败后同时重试两次的场景核对消息只落盘一次。 |
| 查看延迟监测详情 | 「抖动」与最高和最低延迟的差值相同，一次尖峰会持续影响整段记录的读数。 | 用相邻成功采样的延迟变化量计算均值。三个成功样本 10、11、50 ms 得到 20 ms，只有一个样本时显示空值。 |

群聊量测使用同机同进程的 100,000 条合成 JSONL 记录，比较旧算法与索引方案。100 次热查询合计从 151.4 ms 降至 0.3 ms；首次读盘和查询从 75 ms 增至 81 ms，保留消息后的堆占用从 34.4 MiB 增至 39.7 MiB。首次打开仍要解析整个文件，乱序历史走兼容扫描。该微基准只衡量消息读取和未读计数，公网延迟与桌面渲染另计。

若旧版本迁移后，独立的数据目录里还留有一份 `friends.json`，请先核实它和当前配置目录中哪个文件保存了需要的记录。本次修复只切换可确认归属的文件，历史遗留副本保留在原位置。

## 验收环境

2026-11-06 至 11-07，Windows、Node.js 22.18.0。一次隔离完整回归 `node --test tests/*.test.mjs` 共 356 项通过，跳过 0 项。收尾时定向复核好友与目录相关的 24 项，以及最后调整的目录和翻译启动 2 项，均通过，数字含重叠用例。Edge 界面冒烟另计 31 项。最终 Windows EXE 构建及隔离启动通过，核对了首页、功能注册、地图引擎和资源完整性。

游戏实测使用临时配置、临时离线账户和已有游戏缓存。翻译实测让另一个服务占用 8636，真实 Python 工作台在 8637 启停成功；旧版独立 EXE 的缓冲行为由无横幅子程序模拟。桌面自动更新的覆盖使用测试资产和更新弹窗，未替换玩家正在使用的启动器。
